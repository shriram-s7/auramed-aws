1. EXECUTIVE SUMMARY & CLINICAL MISSION
====================================================================================================
AuraMed Healthcare is an advanced, multimodal Artificial Intelligence diagnostic and clinical decision
support platform designed specifically for women's healthcare. The platform delivers real-time,
high-precision screening across three high-impact medical domains:

1. Breast Cancer Screening:
   Early detection of malignant tissue abnormalities through a dual-stream multimodal framework
   combining digital mammograms with patient-specific clinical and genetic risk factors.

2. Cervical Cancer Cytology Classification:
   High-resolution classification of cervical smear microscopy images across five cytological and
   dysplastic stages using a state-of-the-art Vision Transformer (ViT).

3. Polycystic Ovary Syndrome (PCOS) Detection:
   Automated detection of ovarian morphological abnormalities in pelvic ultrasound scans, coupled
   with Explainable AI (Grad-CAM heatmaps) to highlight follicle clustering and hormonal biomarker
   profiling aligned with the Rotterdam Diagnostic Criteria.

The platform is designed to assist radiologists, gynecologists, and clinical oncologists by providing
not only binary classifications or stage predictions, but also deep clinical reasoning, longitudinal
risk projections, actionable medical recommendations, and visual interpretability.

2.1 Local Execution Stack:
--------------------------
For rapid on-premise evaluation and local testing, the system provides integrated Windows batch launchers:
- `run_all.bat`: Concurrently spawns the backend and frontend in dedicated terminals.
- `run_backend.bat`: Initiates the Python virtual environment (.venv) and launches Uvicorn on
  http://127.0.0.1:8000 with hot-reload enabled.
- `run_frontend.bat`: Sets the temporary directory and npm cache, launching the Vite development
  server on http://localhost:5173.

2.2 Cloud Production Architecture:
----------------------------------
- Compute Engine: AWS EC2 instance hosting the Python runtime, PyTorch (torch, torchvision, timm),
  Scikit-Learn, and FastAPI.
- API Layer: AWS API Gateway configured with a HTTP proxy route ({proxy}+) forwarding calls to the
  EC2 public IP address at port 8000.
- Frontend Hosting: AWS Amplify directly connected to the project's Git repository for continuous
  deployment (CI/CD) and automated build generation.
- Persistent Session & Test Store: Designed for Amazon DynamoDB integration, capturing every patient's
  diagnostic transaction, input biomarkers, predicted outcome, confidence score, and base64 Grad-CAM
  visualization map.

2.3 Networking, Security & Environment Isolation:
-------------------------------------------------
- CORS Middleware: Configured in FastAPI via CORSMiddleware with wildcard allowances during prototyping,
  readily restricted to the Amplify production domain for deployment.
- Environment Injection: Frontend connects through dynamic configuration via `.env` file containing
  `VITE_API_BASE_URL` (e.g., http://localhost:8000 or the AWS API Gateway endpoint).

3.1 SUBSYSTEM 1: BREAST CANCER MULTIMODAL FUSION MODEL
----------------------------------------------------------------------------------------------------
Location: `auramed full setup/backend setup/breast/`
Weight Files:
  - `breast_model.pth` (94,361,691 bytes / ~94.4 MB)
  - `clinical_model.pkl` (26,141,369 bytes / ~26.1 MB)

3.1.1 Image Processing Stream (ResNet-50):
- Architecture: 50-layer deep Residual Convolutional Network (torchvision.models.resnet50).
- Modification: The final 1000-class fully connected classification layer is replaced with a single
  linear projection node:
    `image_model.fc = nn.Linear(image_model.fc.in_features, 1)`
- Preprocessing Pipeline:
  1. Image loading and conversion to standard 3-channel RGB.
  2. Resizing to (224, 224) spatial resolution via bilinear interpolation.
  3. Conversion to PyTorch floating-point tensor scaled to [0.0, 1.0].
  4. Tensor unsqueezing to yield a 4D batch tensor of shape `(1, 3, 224, 224)`.
- Inference Execution:
  1. Model set to evaluation mode (`image_model.eval()`).
  2. Forward inference within a `torch.no_grad()` context block.
  3. Activation: Passed through a sigmoid non-linearity to map raw logit output to a normalized
     image-derived malignancy probability:
       `image_score = torch.sigmoid(output).item()`

3.1.2 Clinical Tabular Stream (Random Forest Classifier):
- Architecture: `sklearn.ensemble.RandomForestClassifier` trained on comprehensive epidemiological
  and clinical risk parameters.
- Model Storage: Serialized using `joblib`.
- Feature Schema: Enforces exact validation against the 11 clinical features stored in
  `clinical_model.feature_names_in_`:
    1.  `breast_density`        (Integer 1-4: BI-RADS density category)
    2.  `age`                   (Integer: Patient chronological age in years)
    3.  `family_history`        (Binary 0/1: Family incidence of breast/ovarian cancer)
    4.  `hormonal_risk`         (Binary 0/1: Hormone replacement therapy or early menarche)
    5.  `obesity`               (Binary 0/1: BMI >= 30 indicator)
    6.  `menopause_status`      (Binary 0/1: 0 = Premenopausal, 1 = Postmenopausal)
    7.  `high_risk_age`         (Binary 0/1: High-risk chronological age bracket)
    8.  `density_risk`          (Binary 0/1: Elevated mammographic parenchymal density risk)
    9.  `genetic_risk_score`    (Float: Hereditary/genetic risk assessment score, e.g., 0.0 - 1.0)
    10. `lifestyle_risk`        (Float: Composite lifestyle risk factor score, e.g., 0.0 - 1.0)
    11. `combined_risk_index`   (Float: Integrated clinical risk index, e.g., 0.0 - 1.0)
- Missing Value Strategy: Any omitted clinical feature is safely filled with a default baseline value (0),
  guaranteeing deterministic alignment with expected feature column order.
- Inference Execution:
  Probability evaluation extracted via:
    `clinical_score = float(clinical_model.predict_proba(features)[0][1])`

3.1.3 Multimodal Late Fusion Engine:
The system implements a weighted late fusion mechanism combining visual mammographic patterns with
systemic patient risk metrics:
    `final_score = (0.7 * image_score) + (0.3 * clinical_score)`

Diagnostic Stratification:
- `final_score > 0.60` -> "HIGH RISK OF BREAST CANCER"
- `0.40 < final_score <= 0.60` -> "MODERATE RISK"
- `final_score <= 0.40` -> "LOW RISK"

3.1.4 Rule-Based Clinical Explanation & Recommendation Engine:
The inference layer dynamically synthesizes human-readable clinical rationale based on patient data:
- Mammographic Rationale: Triggered if `image_score > 0.6`:
  "Suspicious tissue patterns detected in mammogram."
- Hereditary Rationale: Triggered if `family_history == 1`:
  "Family history increases cancer probability."
- Age Factor Rationale: Triggered if `age > 50`:
  "Age above 50 increases risk."
- Density Factor Rationale: Triggered if `breast_density >= 3`:
  "High breast density detected."
- Metabolic Factor Rationale: Triggered if `obesity == 1`:
  "Obesity contributes to hormonal risk."

Actionable Medical Recommendations:
- High Risk Tier:
  * "Immediate radiologist consultation"
  * "Diagnostic mammography"
  * "Biopsy if abnormality confirmed"
- Moderate Risk Tier:
  * "Repeat screening in 2 months"
  * "Ultrasound evaluation"
  * "Lifestyle risk reduction"
- Low Risk Tier:
  * "Routine screening after 2 year"
  * "Maintain healthy lifestyle"

3.1.5 Longitudinal Risk Timeline Forecasting Model:
To assist preventative medical planning, the engine computes forward-looking risk probabilities:
- 6-Month Projected Risk: `min(final_score * 1.10, 1.0)`
- 1-Year Projected Risk:  `min(final_score * 1.25, 1.0)`
- 3-Year Projected Risk:  `min(final_score * 1.50, 1.0)`
These values are delivered to the frontend for interactive dynamic curve rendering via Recharts.

3.2 SUBSYSTEM 2: CERVICAL CANCER VISION TRANSFORMER (ViT) CLASSIFIER
----------------------------------------------------------------------------------------------------
Location: `auramed full setup/backend setup/cervical/`
Weight Files:
  - `aura_med_cervical_v1.pth` (343,270,179 bytes / ~343.3 MB)

3.2.1 Deep Learning Architecture (ViT-Base Patch16-224):
- Framework: `timm` (PyTorch Image Models)
- Model Identifier: `vit_base_patch16_224`
- Transformer Specifications:
  * Patch Size: 16x16 pixels
  * Input Resolution: 224x224 pixels (yielding 14x14 = 196 image token patches + 1 [CLS] token)
  * Hidden Embedding Dimension (D): 768
  * Transformer Encoder Layers: 12 self-attention blocks
  * Attention Heads: 12 heads per block
  * Multi-Class Linear Classifier Head: 5 output logits (`num_classes=5`)

3.2.2 Cytological Image Processing Pipeline:
- Supported Formats: `.bmp` (Standard digital cytology microscopy format), `.jpeg`, `.png`,
  and `application/octet-stream`.
- Normalization Parameters:
  * Resize to (224, 224)
  * Tensor scaling to [0, 1]
  * Standard ImageNet 3-channel normalization:
    `mean = [0.485, 0.456, 0.406]`
    `std  = [0.229, 0.224, 0.225]`
  * Batch dimension expansion to `(1, 3, 224, 224)`.

3.2.3 5-Stage Histopathological Categorization:
The network outputs probabilities across five distinct cytological cell categories:
1. `Dyskeratotic`:
   Atypical keratinized squamous cells showing marked nuclear abnormalities and premature
   cornification. Correlates with high-grade dysplasia and aggressive squamous intraepithelial lesions.
2. `Koilocytotic`:
   Cells displaying classic signs of Human Papillomavirus (HPV) infection: prominent nuclear
   enlargement, hyperchromasia, wrinkled nuclear membranes, and a clear perinuclear halo.
3. `Metaplastic`:
   Squamous metaplastic cells representing physiological or reactive transformation at the squamo-
   columnar junction (transformation zone).
4. `Parabasal`:
   Small, immature squamous cells derived from the deeper layers of the epithelium; commonly observed
   in atrophic smears, severe inflammation, or deep erosive dysplasia.
5. `Normal`:
   Healthy, well-differentiated superficial and intermediate mature squamous epithelial cells with
   normal nucleo-cytoplasmic ratio.

3.2.4 Bethesda System Clinical Progression Matrix:
The frontend maps model predictions to standardized clinical oncology classifications:
- Normal       -> Very Low Risk -> Healthy cervical epithelium; routine follow-up.
- CIN1 / Mild  -> Low Risk      -> Mild dysplasia in lower third of epithelium; repeat in 12 months.
- CIN2 / Mod   -> Moderate Risk -> Dysplasia in middle third; colposcopy & preventive treatment.
- CIN3 / Sev   -> High Risk     -> Severe dysplasia > 2/3 of layer; immediate excisional treatment.
- Carcinoma    -> Critical Risk -> Invasive neoplastic cells penetrating basement membrane.

3.3 SUBSYSTEM 3: PCOS ULTRASOUND CLASSIFIER & EXPLAINABLE AI (XAI)
----------------------------------------------------------------------------------------------------
Location: `auramed full setup/backend setup/pcos/`
Weight Files:
  - `pcos_vision_model.pth` (94,372,757 bytes / ~94.4 MB)

3.3.1 Convolutional Backbone (Modified ResNet-50):
- Class Definition: `PCOSVisionModel(nn.Module)`
- Feature Extractor: ResNet-50 backbone with standard residual bottleneck layers.
- Custom Classification Head:
    ```python
    self.resnet.fc = nn.Sequential(
        nn.Dropout(0.5),
        nn.Linear(num_ftrs, 2)
    )
    ```
- State Dict Adaptability: The loader dynamically strips prefix keys (e.g. `network.`) to ensure
  seamless compatibility between training checkpoints and local inference instantiation.
- Binary Target Output:
  * Class Index 0: `Healthy`
  * Class Index 1: `PCOS`

3.3.2 Explainable AI via Grad-CAM (Gradient-Weighted Class Activation Mapping):
Medical diagnosis demands transparent model interpretability. AuraMed incorporates a real-time
Grad-CAM engine directly into the inference path:
- Target Convolutional Layer: `model.resnet.layer4[-1]` (the final residual bottleneck block).
- Forward Hook: Records activation feature maps `A^k \in \mathbb{R}^{C \times H \times W}`.
- Backward Hook: Records backpropagated gradients `\frac{\partial Y^c}{\partial A^k}`.
- Computation Workflow:
  1. Forward pass computes class logits `Y`.
  2. Argmax identifies predicted class `c = \text{argmax}(Y)`.
  3. `model.zero_grad()` clears residual gradients.
  4. Backward pass executed on winning logit: `output[0, c].backward()`.
  5. Global Average Pooling computes channel importance weights:
       `\alpha_k^c = \frac{1}{Z} \sum_i \sum_j \frac{\partial Y^c}{\partial A_{i,j}^k}`
  6. Weighted linear combination of feature maps:
       `L_{\text{Grad-CAM}} = \text{ReLU}\left(\sum_k \alpha_k^c A^k\right)`
  7. Rectified linear unit (ReLU) ensures only features contributing positively to the diagnosis
     are visualized.

3.3.3 Color Mapping, Visual Blending & Base64 Streaming:
- Normalization: Heatmap array normalized to floating-point range [0.0, 1.0].
- Spatial Scaling: Resized via OpenCV to (224, 224) matching the input dimensions.
- Pseudocolor Encoding: Transformed via `cv2.applyColorMap(..., cv2.COLORMAP_JET)`:
  * Red/Yellow: High model attention (peripherally displaced micro-follicles, thickened stroma).
  * Blue/Cyan: Low model attention (background anatomical regions).
- Alpha Blending:
    `overlay = cv2.addWeighted(img_cv, 0.6, heatmap_colored, 0.4, 0)`
- Output Serialization: Encoded as JPEG bytes in memory and converted to a base64 string,
  returned directly inside the JSON payload for immediate zero-latency browser rendering.

3.3.4 Rotterdam Diagnostic Biomarker Correlation:
The PCOS module correlates image findings with the Rotterdam Consensus criteria:
- Ultrasound criteria: Increased ovarian volume (> 10 ml) and/or >= 12 follicles per ovary (2-9 mm).
- Clinical & Endocrine parameters processed by the platform:
  * Weight (kg), Height (cm), and calculated BMI
  * Luteinizing Hormone (LH) & Follicle-Stimulating Hormone (FSH)
  * LH/FSH Ratio (ratio > 2.0 indicates characteristic neuroendocrine dysregulation)
  * Anti-Müllerian Hormone (AMH - elevated in PCOS due to excessive pre-antral follicle count)
  * Serum Androgen Level (evaluates hyperandrogenism: hirsutism, acne, alopecia)

4.1 Core Server Engine & Middleware Setup:

- Fault-Tolerant Model Import: Dynamically imports `breast.inference`, `cervical.inference`, and

4.2 Patient Session Lifecycle Endpoints:
- `POST /patient/start`:
  * Request Body: `PatientStartRequest` (JSON)
    `{ patient_id: string, name: string, age: string, phone: string }`
  * Response: `{ status: "session_started", patient_id: "...", timestamp: "..." }`
  * Clinical Purpose: Validates patient registration and assigns a unique session timestamp.

- `POST /patient/test/save`:
  * Request Body: `PatientSaveRequest` (JSON)
    `{ patient_id, test_type, model_input, prediction, confidence, heatmap, overlay, overlay_map }`
  * Response: `{ status: "success", message: "Test results saved" }`
  * Storage: Maintained in an in-memory session record database `patient_tests_db`, structured
    for direct forwarding to AWS DynamoDB.

4.3 Model Prediction Endpoints:
- `POST /predict/breast`:
  * Content-Type: `multipart/form-data`

5.1 Technology Stack & State Management:
- Single-page application designed with an oncology-grade aesthetic (teal, slate, rose, and amber).

  to access any diagnostic module, they are automatically redirected to the dashboard. Modules in the

4. `CervicalCancer.jsx`: High-resolution cytology upload and automated stage classification workbench.

5.4 Reusable Clinical UI Components:
- `PatientForm.jsx`: Dynamic registration form with start-session/lock-session state toggling.

8. STRENGTHS, DEFENSIVE DESIGN CHOICES & FUTURE ROADMAP
====================================================================================================

Architectural Strengths:
1. Multimodal Diagnostic Synergy: By fusing imaging features with clinical risk scores (70/30 late
   fusion), the breast cancer module significantly reduces false negatives compared to isolated
   mammography.
2. Clinical Explainability (XAI): The integrated Grad-CAM engine in the PCOS module provides visual
   evidence for algorithmic predictions, building trust with clinicians.
3. Robust Fallback Design: The backend contains graceful exception handling and mock model fallbacks,
   preventing server crashes during missing weight file scenarios or front-end testing.
4. Patient Session Protection: Diagnostic workflows cannot be triggered anonymously; session integrity
   guarantees that all diagnostic inferences are linked to verified patient records.

Recommended Future Enhancements:
1. Native DICOM Support: Incorporate `pydicom` to support direct PACS (Picture Archiving and
   Communication System) integration for hospital-grade DICOM image ingestion.
2. Relational Database Migration: Upgrade the in-memory/DynamoDB test store to an ACID-compliant
   PostgreSQL database via SQLAlchemy or Prisma to support complex clinical cohort queries.
3. Multi-View Mammogram Fusion: Extend the breast cancer vision pipeline to simultaneously evaluate
   both Craniocaudal (CC) and Mediolateral Oblique (MLO) views.
4. Federated Learning & Edge Inference: Support ONNX runtime export for low-latency edge deployment
   directly on portable ultrasound carts and digital microscope workstations.
